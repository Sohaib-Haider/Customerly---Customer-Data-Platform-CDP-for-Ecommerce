The 13 regression tests exercise source/tenant separation, leading zeros, fractional-integer rejection, explicit booleans, event-ID stability across chunk sizes and rejected rows, required behavior months, returns and decimal precision, invoice consistency, repeated redemptions/promotions, source-local line times, zero quantities, coupon rosters/links, reused campaign IDs, global streamed duplicate detection, failed-publication preservation, successful directory publication/backups, PostgreSQL-compatible integer CSV tokens, and promotion-stream stability across chunk sizes. A single test can cover several related assertions.

Real-source discoveries incorporated into implementation:

- Seven messaging campaign IDs are reused between bulk and transactional campaigns. Both source type and source ID form the relationship key.
- Some message customers do not occur in the first-purchase file. The streaming mapper adds these customers without inventing a purchase date.
- Students day and Cyber Monday Sale both occur on 2021-01-25 in the source. Holiday uniqueness includes the name so neither is removed.
- Some Retail invoice lines have different local timestamps. Source line timestamps are retained rather than selecting an arbitrary order time.

The Retail exception condition is an intentional preservation gate, not a completed clean export. Supporting anonymous orders would require an explicit nullable-customer schema/feature policy; the implementation does not create fake customer identities or silently authorize that policy. Full runs must also resolve any further source exceptions surfaced by validation. Currency comparability, coupon gross/net semantics and customer/product feature storage remain documented coverage limitations.
